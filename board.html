W1 — remove.bg wrapper + confidence-flagged vision schema.
W1 · Reused the existing lib/ai/wardrobeVision.ts (already the app's one approved wardrobe vision one-off, previously only used by the single-item AddItemFlow) rather than building a second pipeline -- extended its tool schema with needs_review: string[] (field names the model flags as genuinely unsure, e.g. unreadable brand logo) instead of forking a new tool. New lib/wardrobeBgRemoval.ts wraps remove.bg: sends the compressed photo, requests bg_color=F2F1ED (one fixed neutral off-white baked into every cutout, not a CSS var, so the catalogue looks uniform regardless of theme) -- on ANY failure (missing key, non-200, network error) it returns the original photo bytes untouched with bgRemoved:false rather than throwing, so a remove.bg outage never loses a photo.
W2 — /process (per-photo pipeline, no DB writes) + /confirm (batch save) API routes.
W2 · POST /api/wardrobe/bulk-import/process takes one compressed photo, runs bg-removal then vision on the CUTOUT (background clutter removed first, which should improve identification accuracy too), and returns the proposed fields + the cutout as base64 -- writes nothing to the DB, so an abandoned batch leaves zero orphaned rows/storage objects. If vision itself throws, still returns the cutout with every field flagged needs_review rather than losing the photo. POST /api/wardrobe/bulk-import/confirm takes the final array (fields + cutout bytes) and uploads+inserts each item independently in a loop -- one item's failure is reported by name/index and does NOT abort the rest of the batch (no silent failures, no all-or-nothing batch loss).
W3 — BulkImportFlow UI: multi-file/folder picker, review grid, bulk edit, duplicate flags.
W3 · New components/wardrobe/BulkImportFlow.tsx, full-screen overlay matching MediaWidget's CatalogueModal pattern (not the small BottomSheet, since a review grid needs real space). Pick screen offers two file inputs: a plain multi-select (mobile-friendly, accept="image/*" multiple) and a second webkitdirectory-attributed input for a desktop folder import -- same underlying processFiles() pipeline either way, no separate CLI/script path needed. Photos process sequentially with a progress bar; each photo's failure (network error, processing error) still produces a card in the review grid with every field flagged needs_review rather than silently vanishing. Review grid: each card shows the cutout thumbnail, inline name/type/colours/brand/season-chips/tags with an amber border on any AI-flagged needs_review field, a "More fields" accordion for size/condition/price/acquired-date/notes, and a per-card "Remove from batch" (discards locally, nothing persisted yet). Selecting 1+ cards surfaces a sticky bulk-action bar (set type/brand, add a season/tag to every selected card at once) styled like the FoodClient selection bar from an earlier session. Duplicate detection: fetches the full unfiltered existing wardrobe once at batch start, keys on type+brand+first-colour, checks both against existing items AND earlier items already in the same batch, and renders a "Possible duplicate of X" warning rather than silently creating a second entry.
